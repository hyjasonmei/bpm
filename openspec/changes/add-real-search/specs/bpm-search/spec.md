## ADDED Requirements

### Requirement: SearchService provides text + filter queries

The system SHALL expose `ISearchService` with methods to search ProcessInstances, Users, Comments, and a global combined search. Each search method SHALL accept a free-text query (with FTS5 MATCH semantics) plus optional structured filters (spec_code, status, date range, amount range, etc.). Results SHALL be auth-filtered: regular users see only instances they initiated or are/were assigned to; admins see all in tenant.

#### Scenario: Find own cases by keyword

- **GIVEN** Wilson submitted a LEAVE instance with reason "出差日本"
- **WHEN** Wilson calls `GET /api/search/instances?q=日本`
- **THEN** the result contains his instance with a snippet around "日本"

#### Scenario: Cross-user case hidden from non-admin

- **GIVEN** Yang submitted an instance Wilson is NOT involved with
- **WHEN** Wilson searches and Yang's instance text would otherwise match
- **THEN** Yang's instance is NOT in Wilson's results

#### Scenario: Admin sees all

- **WHEN** an admin runs the same search
- **THEN** instance results include both Wilson's and Yang's cases

### Requirement: Filters narrow by structured fields

The instance search SHALL support filters: `spec_code`, `status`, `initiator_user_id`, `started_after`, `started_before`, `completed_after`, `completed_before`, `amount_min`, `amount_max`. Filters combine with AND semantics with the text query.

#### Scenario: Filter by spec_code

- **WHEN** Wilson searches with `?spec_code=LEAVE`
- **THEN** only LEAVE instances appear

#### Scenario: Date range narrows

- **WHEN** Wilson searches with `started_after=2026-05-01&started_before=2026-05-31`
- **THEN** only instances started in May 2026 appear

#### Scenario: Amount range filter

- **WHEN** an admin searches purchase instances with `amount_min=50000&amount_max=200000`
- **THEN** results include only instances whose canonical amount is in the range

### Requirement: SaveChanges interceptor keeps index in sync

A `SearchIndexUpdateInterceptor` SHALL hook into EF SaveChanges and update the corresponding FTS5 row whenever a ProcessInstance / Comment / User entity is created or updated. Updates happen in the same DB transaction. Search results SHALL never be staler than the most recent SaveChanges.

#### Scenario: New comment indexed immediately

- **GIVEN** Wilson posts a Comment with body "請補上醫師簽章"
- **WHEN** the SaveChanges commits
- **THEN** searching for "醫師" finds that Comment

#### Scenario: Updated form data indexed

- **GIVEN** an existing ProcessInstance has searchable_text including "出差北京"
- **WHEN** a userTask submission changes destination to "出差東京"
- **THEN** searching "東京" finds the instance; searching "北京" no longer finds it

### Requirement: Snippet highlighting uses FTS5 snippet()

Search results SHALL include a `snippet` field generated by SQLite FTS5's `snippet()` function (or Postgres `ts_headline()` after migration). The snippet SHALL include surrounding context with `<b>` / `<mark>` markers around the matched terms, suitable for safe rendering in the frontend after HTML-escaping.

#### Scenario: Snippet contains match

- **WHEN** Wilson searches "日本"
- **THEN** each result's `snippet` field includes "...出差<mark>日本</mark>5天..." style highlighted text

### Requirement: Pagination caps page size at 100

The search endpoints SHALL accept `page` and `size` query parameters; `size` is capped at 100. Default `page=1, size=20`. Response includes `{ items, total, page, size }`.

#### Scenario: Default pagination

- **WHEN** the caller omits page / size
- **THEN** the response has page=1, size=20, items.length ≤ 20

#### Scenario: size=200 capped

- **WHEN** the caller requests size=200
- **THEN** size is silently capped at 100; items.length ≤ 100
