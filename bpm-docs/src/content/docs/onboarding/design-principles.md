客戶描述流程時講的是習慣，不是規則。導入員的價值是把習慣翻成**明確、可執行、不會卡**的流程設計。

## 原則

1. **關卡越少越好** — 每多一關就多一個卡點。問「這關真的有人會退件嗎？」——從來不退的關卡改成通知即可
2. **簽核對象用角色，不用人名** — 「送給 HR_MANAGER」而不是「送給 Henry」；人會離職，角色不會。角色成員在 [User & Role](/backend/user-role/) 維護
3. **條件路由要可判定** — 金額、天數、假別這種欄位值可以自動判；「重要的案子」不行
4. **退回要指定去處** — 退回到申請人改單重送？還是整案作廢？每個退件都要講清楚
5. **並簽想清楚門檻** — 全簽（一人退全退）適合把關；M/N 門檻適合委員會表決
6. **一開始就想例外** — 主管休假（[委任代理人](/frontend/delegation/)）、角色沒人（[Doctor](/backend/doctor/) 會抓）、申請人離職

## 常見翻譯

| 客戶說 | 設計成 |
|---|---|
| 「主管簽一下」 | 一關主管簽核，退回可改單重送 |
| 「金額大要老闆看」 | 條件加簽：金額 ≥ N → 多一關 |
| 「大家都要同意」 | 並簽全簽（AND） |
| 「過半就好」 | 並簽門檻（M/N） |
| 「HR 留個紀錄」 | 歸檔關（不簽核只確認）或通知 |
